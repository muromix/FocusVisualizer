# Focus Visualizer - 全体仕様書 (Master Specification - Japanese)

## 1. アプリケーション概要 (Overview)
Sonyのαシリーズ（a7R Vなど）で撮影されたRAW画像（ARW）から、メタデータ（フォーカス位置、モデル情報等）を抽出し、Lightroomとのリアルタイム同期を保ちながら高精度に可視化するフルスタック・ビューワー。

### セキュアな通信基盤 (Secure IPC Foundation) - *2026/02/23 導入*
Electronの最新ベストプラクティスに基づき、レンダラープロセスの権限を最小化。
1.  **コンテキスト分離 (Context Isolation)**: レンダラー(`renderer.js`)からNode.js/Electron APIへの直接アクセスを遮断し、グローバル名前空間を汚染しない安全なブリッジを実現。
2.  **プリロード・ブリッジ (Preload Bridge)**: `preload.js` 内で信頼されたAPIのみを `window.api` として公開。
3.  **ファイルシステム制御**: レンダラーからの直接的なファイル書き込み (`fs.writeFileSync`) を廃止。メインプロセスがIPC経由で要求を受け取り、安全性を検証した上で代行実行する。
4.  **CSP (Content Security Policy)**: 内部サーバー(127.0.0.1)へのリクエストのみを許可し、外部ドメインへの予期せぬ通信をブロック。

## 3. 主要機能 (Main Features)

### 📸 フォーカス可視化 & 解析
*   **高速表示**: RAW画像でも0.3秒以下の表示を実現。
*   **フォーカス可視化**: 緑色のAF枠、トラッキング状態を表示。
    - *(Sony AI 認識 / Tag9401 解析は現在ブラッシュアップのため一時停止中)*
*   **フォーカスピーキング**: 合焦部をドット表示。50msの超速解析。
*   **日本語パス対応 (Mojibake Rescue)**: 日本語フォルダ内でも完璧に動作。

### 🔄 Lightroom 同期
*   **評価同期**: レーティング(0-5)、カラーラベル(6-9)、およびフラグ（Pick/Reject）を即座にLightroomへ反映。

### 💎 画質制御 (Quality Mode)
| モード | 解像度 | 特徴 | 初期値 (Default) |
| :--- | :--- | :--- | :--- |
| **Speed** | 1600px | **爆速・シンプル** | **Full/Lite モード共通** |
| **Full** | オリジナル | 究極のピント確認 | 手動またはQキーで移行 |

*   **Liteモードの進化 (Power-Up)**: 
    - **フル機能解放**: コナミコマンド等でアンロックされたパワーユーザーに限り、Liteモードでもレーティング、ラベル、フラグ、画質切替などのフルショートカットが利用可能（レイアウト切替 `I` を除く）。
    - **GUIミニマリズム**: アンロック後も昇格ボタン等のGUIを出さず、ショートカットキーのみで操作を完結させるストイックな設計。
    - 初期画質は選別テンポを重視し、引き続き爆速の **Speed画質** がデフォルトとなります。

*   **マルチディスプレイ適応 (Display Sticky)**: 
    - **LRC追従配置**: 起動時、マウスカーソルがあるディスプレイ（＝LRCを操作している画面）を検出し、そのモニター内にウィンドウを生成します。
    - **画面固定スナップ**: モード切替やリサイズ時、現在ウィンドウが表示されているモニターを自動検出し、その WorkArea 内で配置を完結。拡張モニター使用時の意図しない画面移動を根絶しました。

*   **画質ロックとナビゲーション制限 (Quality Lock & Blocking)**: 
    - **Lキー (Lock)**: 有効にすると、FULL画質（または解析完了）の描画が完了するまで次の画像への移動を物理的に制限します。これにより、低画質な状態での誤判定を防ぎます。
    - **動的スキップ**: ロックが無効な場合、重い現像処理（DNGの現像など）の途中でもユーザーの操作を最優先し、即座に次の画像へジャンプします。

## 4. 開発理念：写真選別特化 (Selection Specialized) - *2026/03/05 定義*
本プロジェクトは、汎用的な画像編集ソフトを目指すのではなく、撮影後の膨大なRAW画像から「ベストショットを最速で選び抜く（Culling）」ための専門ツールを目指します。

1.  **「真実の現像」路線の堅持**: 
    Lightroom上での二次的な加工（クロップ、露出補正）をあえて追従せず、カメラが記録したそのままの「すっぴん現像（rawpy）」を行います。これにより、メタデータと座標の100%一致を保証します。
2.  **判断を促すUI**: 
    ただ画像を見せるだけでなく、被写体認識（瞳・顔・動物）の状態やフォーカス位置を可視化することで、ユーザーが「迷わず」判断を下せる体験を提供します。
3.  **独立性と軽快さ**: 
    Lightroomの重いプレビュー生成を待つことなく、独自の高速プレビュー抽出エンジン（ExifTool & rawpy）で選別ワークフローを加速させます。

## 5. 操作・ショートカットキー (Keyboard shortcuts)
| キー | アクション |
| :--- | :--- |
| `Space` | **精密ターゲット・ズーム** (等倍 ↔ 全体) |
| `←` / `→` | 写真送り (Lightroom連動) |
| `Q` | 画質モード切替 |
| `L` | 画質ロック |
| `P` | **ピーキング** ON/OFF |
| `A` / `X` / `U` | フラグ (採用 / 却下 / なし) |
| `1` - `5` | レーティング |
| `M` | **モード切替** (Full ↔ Lite) ※アンロック後推奨 |

*注: アンロック済みのパワーユーザーは、Liteモードでも上記すべてのショートカット（Iキーを除く）が使用可能です。*

## 9. 更新履歴 (Changelog) - *最新のみ*
- **2026/03/31**: **「Minimalism & Multi-Display Sticky Behavior」**
  - **Liteモードのフル解放**: コナミコマンドによるアンロック後であれば、Liteモードでも全てのセレクト操作ショートカット（1-9, Q, A, X, U）が有効化されるように `InputManager.js` の封印を精密に解除。
  - **GUIミニマリズム**: アンロック後も「Full Modeへの昇格」ボタンを表示しないように変更。GUIノイズを削ぎ落とし、ショートカットキー操作（Mキー）への一本化を徹底。
  - **ディスプレイ追従ロジック**: `screen.getDisplayMatching()` およびマウスカーソル位置によるディスプレイ検知を導入。初回起動はLRCのある画面へ、モード切替は現在表示中の画面へと、ウィンドウが意図通りに「吸い付く」挙動を実現。
  - **Zenモード設計の洗練**: 複雑な自動非表示モードを新設する代わりに、既にミニマルなLiteモードを解放することで、理想的な没入体験をシンプルに提供。
  - **アトミック状態更新 (Flicker-Free 2.0)**: 画像の差し替えと表示倍率（ズーム・フィット）を完全に同時に適用する `markImageLoadedWithView` を実装。読み込みの隙間に画像が一瞬だけ巨大化（等倍表示）する「チカつき」を物理的に根絶。
  - **DNG爆速画像送り**: DNGファイルにおいて、SPEEDモード時でも重い現像処理 (`rawpy`) を強制していたロジックを修正。ARW同様に埋め込みJPEG抽出へのフォールバックを徹底し、DNG混在環境での「詰まり」を解消。
  - **右クリック・ナビゲーター修正**: Viewerの右クリックコンメニューから「次へ・前へ」の操作が逆転していた（または動かなかった）問題を、LrCプラグイン側のパースロジック修正により解決。
  - **ゼロ・ラグ同期の調整**: 画像ロード完了を待ってから情報の表示を行う「シンクロ表示」を試行したが、選別テンポを重視し「情報は即座に表示」という元の挙動にコミット。
- **2026/03/13**: **「4層のメタデータ要塞 (Metadata Persistence Fortress)」**
  - **情報の不揮発化**: 画質切替やリロード時にレート/ラベルが消失する問題を根絶。
  - **4段構えの防衛**: Heartbeatガード、アクション即時記憶、出口での強制注入、フロントエンド最終防壁の4層を連結し、非同期データの不整合を完全支配。
  - **メタデータ・バックチャネル**: バックエンド側の記憶が揮発している場合、SSE経由でLuaへ再送を要求する `request_metadata` ロジックを実装。
  - **AI連携最速化**: Gemini 2.5/3.1 SDK対応と、Web版Geminiを「外部脳」として活用するゼロコスト・ワークフローを確立。
- **2026/03/11**: **「Solid Frame Navigation & 縦構図表示の統一」**
  - **1枚ずつ確実な描写**: 矢印キーナビゲーションに「描写完了まで次をブロック」するロジックを実装。競合状態の解消と無駄なリソース消費を一掃。
  - **EXIF剥ぎ取りの完全統一**: `_strip_exif_marker()` を全ての画像抽出パス（ExifTool埋め込み・rawpy FULL・DNG balanced）に適用。どの画質でも縦構図が必ず正しく表示される。
  - **キャッシュ・パス欠落バグ修正**: SSEプッシュ時に `data.path` が欠落していたバグを修正。フロントが更新を無視するケースが解消。
  - **計画中: ブラウジングモード (Phase 1-3)**: 280ms閾値による `isBrowsingMode` 検知を計画中。キー押しっぱなし中はSPEEDのみ表示、止まったタイミングでFULLへ静かにアップグレードする仕組みを導入予定。

- **2026/03/06**: **「Flipbook Paging & Turbo Shift (爆速スクロール対応)」**
  - **爆速スクロール最適化**: 行列追加時に3枚以上溜まった場合、中間をスキップして最新にジャンプする「スマート・キャッチアップ」を実装。
  - **メタ解析デバウンス**: 連打中のExifTool負荷を避けるため、静止後0.1秒待機してから解析を開始するロジックを導入。
